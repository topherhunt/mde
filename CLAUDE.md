# MDE -- Markdown Editor

## What this is

A WYSIWYG Markdown editor built with Electron + React + TipTap. See `plan.md` for full design.

## Architecture

**Main process** (`src/index.ts`): Window management, file I/O, IPC handlers, file watching, menu bar, drag-drop at the OS level, DOCX/PDF import conversion. No rendering.

- **Preload** (`src/preload.ts`): Exposes `window.mde` API via contextBridge. All file system access goes through this bridge.
- **Renderer** (`src/renderer.tsx`): React entry point. Imports Bootstrap Icons CSS and app styles.
- **Components** (`src/components/`): App, Sidebar, TabBar, Toolbar, Editor, FindBar, LinkBar, QuickOpen, ConflictBanner, TableMenu.
- **Types** (`src/types.ts`): Shared TypeScript types + `window.mde` declaration.
- **Markdown utils** (`src/utils/markdown.ts`): TipTap <-> Markdown serialization via tiptap-markdown.

## Key decisions

- `tiptap-markdown` handles MD parse/serialize. The TipTap document model is the source of truth while editing.
- TipTap (ProseMirror) for the editor, not raw contenteditable.
- Auto-save is opt-in (disabled by default). When enabled via Settings, saves after 1s of inactivity. Stored as `autosave` in `mde-state.json`. IPC: `get-autosave`, `set-autosave`, `autosave-changed`.
- SINGLE WRITE PATH INVARIANT: `write-file-if-unchanged` is the ONLY IPC that writes a document to disk. There is deliberately no raw `write-file` handler/`writeFile` bridge method -- it was removed so nothing can bypass the hash guard. Cross-file Find & Replace (`FindBar`) also routes through it (with `expectedHash: null`, safe because it writes freshly-read+transformed content and skips open dirty tabs). Do NOT add a raw write-file back; it would be a silent clobber bypass. (Main-process direct `fs.writeFile`s exist only for non-buffer files: state JSON, new-empty-file creation, DOCX/PDF import output, PDF export, launcher scripts.)
- File conflict detection is content-hash based, with two layers. (1) SAFETY BACKSTOP: saving goes through the `write-file-if-unchanged` IPC, which re-reads the file on disk, sha256-hashes it, and refuses the write (returning `{conflict:true}`) if that hash no longer matches the `diskHash` the tab recorded when it last read/wrote the file. A stale buffer therefore cannot clobber a newer on-disk version even if the watcher missed the change entirely -- the renderer raises the red banner instead. Pass `expectedHash: null` to force (new file / Save As). `hash-file` returns the on-disk hash; both use `hashContent()` in index.ts. Each `Tab` carries `diskHash` (set on open, save, reload, rename, silent-reload). (2) LIVE DETECTION: the `file-changed` handler recomputes the disk hash and compares to `tab.diskHash` -- if equal it's a no-op (ignores spurious watcher fires and our own writes); if different and the buffer is clean it silently reloads; if dirty it shows the banner. mtime is no longer used for the change decision (kept only as informational `diskMtime`).
- File watching watches the *containing directory* (filtered by basename, refcounted per dir in `dirWatchers`), NOT the file inode. `fs.watch` on a single file follows the inode, so an atomic save by another program (write temp + rename over original -- what most editors and Claude's file tools do) silently kills the watcher. Watching the directory survives atomic replaces. When the platform reports a null filename, the handler notifies all watched files in that dir and lets the renderer's hash comparison decide.
- Auto-reload proof banner: when a clean buffer is silently reloaded after an external change, a thin blue `.reload-notice` banner naming the file appears. It is `position: absolute` at the top of `.editor-area`, so it OVERLAYS the top of the buffer (never pushes the text down). It fades in, stays 5s, then fades out (`showReloadNotice` sets `reloadNotice`, schedules `hiding: true` at 5s for the fade-out animation, and clears at 5.3s). Purely informational -- positive proof that live detection is working.
- State management: React context + useReducer, no external state lib.
- User preferences (theme, spellcheck, sidebar width, window bounds, last project root, fold state) stored in `mde-state.json` in Electron's userData dir via `loadState`/`saveState` helpers in index.ts.
- Initial file load uses a manual ProseMirror transaction with `addToHistory: false` so undo doesn't clear the buffer. Do not use `editor.commands.setContent()` for initial load -- TipTap's `beforeTransaction` event fires after history has already recorded the transaction.
- The `open-file` macOS event fires before `app.on('ready')` when launched via `mde .`. A `launchFileHandled` flag prevents the ready handler from creating a duplicate default window.
- The `extensions` array and `editorProps` object passed to `useEditor` in Editor.tsx MUST be `useMemo`'d with `[]` deps -- never inline literals. `useEditor` runs an effect on EVERY render that identity-diffs those options against the live editor (it ignores only the `on*` callbacks), so fresh literals make it call `editor.setOptions()` -> `view.setProps()` + `view.updateState()` on every render. That re-syncs the DOM selection during React's commit phase, which ProseMirror's DOM observer can read back and dispatch as a transaction -- transaction -> render -> setOptions -> transaction ... until React aborts with "Maximum update depth exceeded" (minified error #185, thrown from inside `dispatchTransaction`). Anything those closures reference must be module-level or a ref. Relatedly, `MARK_DIRTY` in App's reducer returns the existing state object unchanged when nothing actually differs, so a keystroke in an already-dirty buffer doesn't re-render the whole app.
- Webpack `externals` in the main process (`mammoth`, `turndown`, `turndown-plugin-gfm`, `pdfjs-dist`) are NOT bundled, and electron-forge's WebpackPlugin ships an EMPTY `node_modules` inside `app.asar` -- so without help they throw `Cannot find module 'turndown'` in the packaged app while working perfectly in dev. `forge.config.ts`'s `packageAfterCopy` hook copies each external plus its transitive PROD dependency tree (resolved by walking up `node_modules` the way Node does) into the packaged app. The seed list lives in `webpack.main.config.ts` as `externalPackages`; keep it in sync with `externals`. Adding a new main-process external without adding it there reintroduces the bug.
- Renderer webpack config does NOT use the `@vercel/webpack-asset-relocator-loader`. That loader breaks ESM imports from TipTap packages. It's only needed for native node modules in the main process.
- Code block copy button uses a TipTap NodeView (CodeBlockWithCopy extending the plain `@tiptap/extension-code-block` CodeBlock) so ProseMirror's DOM reconciliation doesn't remove the button. Syntax highlighting is deliberately OFF -- code fences render as uniform unhighlighted text (color `--code-text`). We use the plain CodeBlock, NOT CodeBlockLowlight/lowlight; the `language` fence attribute is still stored and round-tripped through markdown, it just doesn't drive token colors. (The NodeView still adds a `language-<lang>` class to `<code>` but no CSS consumes it.)
- Bootstrap Icons are self-hosted in `src/fonts/` (woff/woff2), imported via CSS in renderer.tsx.
- `confirm()` and `alert()` don't work in Electron's renderer. Use in-app toasts or inline confirmation UI instead.
- ProseMirror decorations (via Plugin with DecorationSet) are used for find-match highlighting and link-bar selection preservation. Always clean up decoration plugins on component unmount.
- File sidebar auto-refreshes via recursive `fs.watch` on the project root (debounced 2s). On macOS this uses FSEvents (kernel-level, zero CPU idle cost).
- PDF text extraction uses `pdfjs-dist/legacy/build/pdf.mjs` with the worker loaded into `globalThis.pdfjsWorker` (fake worker mode). Both `pdfjs-dist` and its worker are webpack externals -- they resolve from `node_modules` at runtime. Do NOT bundle them with webpack; the worker spawning mechanism breaks. Extraction uses position-based line grouping, multi-column layout detection (splits left/right columns when a >15% page-width gap is found), paragraph break detection (>1.5x median line height), and table detection (2+ aligned columns across 3+ consecutive lines).
- Import never mutates the source. The old flow renamed `report.docx` to `report.bak.docx` and filtered `.bak.` files out of the sidebar and quick-open index -- a file the user could see one moment and not the next, under a name they never chose. Now the source stays exactly where it is, and the disambiguation happens at click time: `get-import-target` reports whether `<source>.md` exists, and if it does the renderer shows `ImportExistsDialog` (open the existing Markdown / convert again / cancel) instead of the first-time `ImportConfirmDialog`. `convert-import` takes `{ newCopy?: boolean }`; without it the handler refuses to write over an existing target, with it `nextFreeImportTarget()` walks `<source>.2.md`, `.3.md`, ... to the first free name. There is no code path that overwrites a converted Markdown -- it may contain hand edits.
- DOCX conversion preprocesses mammoth's HTML before turndown: strips `<p>` inside cells, promotes first row `<td>` to `<th>` with `<thead>`/`<tbody>` wrapping, so turndown-plugin-gfm's table rule can convert them. All conversion libraries (mammoth, turndown, turndown-plugin-gfm, pdfjs-dist) are webpack externals in `webpack.main.config.ts`.
- PDF text item joining uses gap-based spacing (>1px gap inserts space) rather than unconditional spaces, to handle PDFs with per-character text items (e.g. web-to-PDF renders).
- PDF heading detection: compares each line's font height to the page's most frequent (body) height. Lines >1.4x body height become headings; distinct sizes map to H1/H2/H3/H4 in descending order.
- PDF column-split detection is suppressed when >30% of lines span both sides of the gap (indicating a wide table, not a two-column layout).
- PDF table cell merging: continuation rows (col 0 empty) are merged into the previous logical row, handling multi-line cell content that spans multiple PDF text lines.
- PDF table run detection allows single-cluster continuation lines mid-run (cell text wrapping to a line with content in only one column).
- PDF conversion escapes lines matching `^\d+\.` to prevent Markdown OL interpretation of numbers like "994164972.".
- tiptap-markdown is configured with `html: false` so raw HTML tags in Markdown (e.g. `<ol>` in body text) are treated as literal text, not parsed as HTML elements. The text node serializer is overridden to skip tiptap-markdown's `escapeHTML` (which converts `<` `>` to `&lt;` `&gt;`), preserving prose like "Apples > oranges." verbatim on save. Standard Markdown character escaping (via prosemirror-markdown's `esc()`) is still applied.
- The Link extension is configured with `autolink: false`, `linkOnPaste: false`, and `addPasteRules: () => []` so typing/pasting a path like `docs/foo.md` stays literal text -- only real Markdown `[text](url)` links are created. A custom `isAllowedUri` (`ctx.defaultValidate(url) || !/^[a-z][a-z0-9+.-]*:/i.test(url)`) is REQUIRED: TipTap's default validator regex `[^a-z+.-:]` treats `.-:` as a character range covering `/`, so it rejects relative links that start with a lowercase letter and contain a slash (e.g. `docs/foo/09-bar.md`). Without the override, those links' marks are dropped while parsing HTML on load, so they collapse to plain text on the next save. The override accepts any scheme-less (relative) URL while still blocking dangerous schemes like `javascript:`/`data:`.
- Following links: Cmd/Ctrl+click on a link in the editor follows it (plain click is left alone so the cursor can be placed inside link text to edit). Implemented as `handleClick` in the Editor's `editorProps` -- it reads the raw `href` via `getAttribute('href')` (the `.href` property would resolve to an absolute `file://` URL) and calls an `onLinkClick` prop. App's `handleLinkClick(href, sourceFilePath)` opens scheme URLs (`http:`/`mailto:` etc.) via `openExternal`; for relative paths it strips any `#anchor`/`?query` and resolves with `resolvePath()` from `utils/paths.ts` against the source file's folder (CommonMark / GitHub / VS Code semantics -- a bare path like `docs/foo.md` is relative to the current file, same as `./docs/foo.md`; `projectRoot` is used only as a fallback for an unsaved buffer). Then `getFileStats` decides: existing file -> `openFile`, directory -> toast, missing -> a `CreateFileDialog` that `createDirectory` + `createFile` + `openFile` on confirm. The `onLinkClick` prop is bound per-tab in the Editor map; inside the Editor a ref (`onLinkClickRef`) bridges it into the once-created ProseMirror click closure.
- Sidebar folder expand/collapse state is lifted to the `Sidebar` component (not `DirectoryNode`) via a `Set<string>` of expanded paths, so it persists across explorer/outline view switches.
- Todo lists are unified with regular bullet list items via an extended `ListItem` with a `checked` attribute (`null` = bullet, `false` = unchecked task, `true` = checked task). All items live in a single `<ul>` -- no separate TaskList/TaskItem node types. Checkboxes are rendered via CSS `::before` pseudo-elements on `li[data-checked]`, with click handling via a ProseMirror plugin. Checked items show strikethrough. The `- [ ]` / `- [x]` input rule detects task syntax typed inside a list item. Markdown serialization prepends `[ ] `/ `[x] `based on the `checked` attr. Enter in a task item creates a new unchecked task (not a bullet). Nesting mixed bullet/task items works naturally since they share one list type.
- Cmd+Enter cycles the current line (or all selected lines) between 3 states: bullet list (`checked: null`), unchecked task (`checked: false`), checked task (`checked: true`). Implemented as a custom TipTap extension (`CmdEnterCycle`) that toggles the `checked` attr via `setNodeMarkup`. Must never insert a line break.
- Tab/Shift+Tab: in lists, indent/outdent; elsewhere, insert a tab character. Always captured by the editor -- never escapes to browser focus behavior. Implemented as a custom TipTap extension (`TabHandler`).
- Cmd+Alt+Up/Down moves the block containing the cursor (paragraph, heading, or list item) above/below its sibling. For list items, operates within the list; for top-level blocks, swaps with the neighboring block. Implemented as the `MoveBlock` TipTap extension.
- Deleting a file via the sidebar also closes any tab open to that file, without adding it to the reopenable closed-tabs queue.
- Keyboard Shortcuts help page opens as a read-only tab. Content loaded from `docs/help/keyboard_shortcuts.md` via webpack `asset/source`. Read-only tabs hide the toolbar, TableMenu, and LinkPreview; the editor caret is transparent. **When adding or changing a keyboard shortcut, always update** `docs/help/keyboard_shortcuts.md` **and the shortcut summary in "What exists" below.**
- `deserializeInto` (used for file-reload on disk change) uses `createNodeFromContent` + manual transaction, not `setContent()`, to avoid the file appearing as raw HTML.
- File explorer context menu (rename, delete, copy path, reveal in OS file manager) and create file/folder use dedicated IPC handlers (`rename-file`, `trash-file`, `reveal-in-finder`, `create-file`, `create-directory`). Delete moves to Trash via `shell.trashItem()`, never permanent delete. Reveal uses `shell.showItemInFolder()`; the menu label is platform-aware ("Reveal in Finder" / "Show in Explorer" / "Show in Folder"). The copy-path item degrades to "Copy File Name" (copies `target.name`) when there's no project root the file sits under -- a relative path is only meaningful inside the project folder.
- Sidebar drag-drop: files and folders can be dragged within the sidebar to move them into different folders (or to root). Dragging onto a file targets its parent folder. Drop targets (folder rows, root header) show a pulsating blue outline. Uses `renameFile` IPC (fs.rename) for the move. Prevents dropping into own descendants or current parent.
- Loose list handling: blank lines (`\n\n`) between list items at the same or parent indent level split them into separate lists on load. A `{LIST_SEPARATOR}` placeholder (plain ASCII) is inserted before parsing to trick markdown-it into splitting, then `cleanParsedListHtml()` replaces the placeholder `<p>` with an empty paragraph in the editor. On save, adjacent lists with an empty paragraph between them produce the `\n\n`. All lists are forced "tight" on load (`data-tight="true"`, `<p>` wrappers inside `<li>` removed) so tiptap-markdown never adds blank lines between items within the same list. The `JoinAdjacentLists` ProseMirror plugin auto-merges adjacent lists of the same type, so deleting the separator paragraph joins them.
- Horizontal rules show a blue outline (`var(--accent)`) when selected via `ProseMirror-selectednode` class.
- Enter at end of a parent list item (one that has a sublist) creates a new first child in the sublist rather than splitting the parent as a sibling. Only triggers when cursor depth is `liDepth + 1` (in the item's own paragraph). Enter on empty nested list items creates siblings (not bare `<p>` elements) -- the list-splitting behavior only applies at root level.
- Code folding: Cmd+. toggles collapse on list items with children. Fold state is stored in a ProseMirror plugin (`foldKey`) as a `Set<number>` of positions. Decorations add `folded` class to the `<li>` and a `fold-badge` widget (`<span>`) at the end of the paragraph. The fold caret is a CSS `::after` pseudo-element (SVG chevron) to the left of the bullet/checkbox. Clicking the caret (left padding area) or badge unfolds via `handleDOMEvents.mousedown`. Cmd+. only folds the item the cursor is directly in (paragraph at depth `liDepth + 1`); cursor in a childless nested item does nothing -- the keystroke is consumed (`return true`) to prevent propagation.
- Click-to-fold hover caret: the `foldKey` plugin also tracks a `hover` position (set via `SET_FOLD_HOVER` meta from a `mousemove` `handleDOMEvent`, cleared on `mouseleave`/toggle/docChange). The hovered item is found by COORDINATES, not DOM target: `view.posAtCoords({left: clamp(clientX into editor), top: clientY})` resolves the position under the pointer's Y, then the innermost `listItem` ancestor is used. This makes the entire row -- including the left gutter where the caret lives -- a hover target, so moving onto the caret never dismisses it. (The caret sits at `left: -33px`, outside the li's box and even left of `.tiptap`, so DOM-target/`closest('li')` detection failed there.) A guard at the top of `mousemove` returns early when `event.target.closest('.fold-caret')` so hovering the caret never recomputes (which would detach it mid-click). When hovering an unfolded foldable item (innermost only), a dim gray `.fold-caret` widget renders to its left -- no parents, no children. The caret carries a `data-tooltip` "Fold sub-list (Cmd + .)" and its `mousedown` dispatches `TOGGLE_FOLD`. In `apply()`, the `TOGGLE_FOLD` check MUST precede `SET_FOLD_HOVER` (TOGGLE_FOLD also resets `hover: null`).
- Clipboard for tables: ProseMirror writes BOTH a `text/html` (real `<table>`, pastes into Word) and a `text/plain` representation. The `SmartClipboard` extension's `clipboardTextSerializer` handles the plain-text side: `tableSliceToTSV()` emits tab-separated rows (`\t` between cells, `\n` between rows; a single cell yields just its text) -- but ONLY when EVERY top-level node of the copied slice is `table`/`tableRow`/`tableCell`/`tableHeader`. A MIXED slice (e.g. Cmd+A over a doc with prose and a table) must fall through to `serializer.serialize(content)`; tiptap-markdown does have a table serializer, so the table comes out as a real Markdown table alongside the headings/paragraphs/lists. Deciding the TSV path on "contains a table anywhere" silently dropped every non-table block from the copy -- do not reintroduce that.
- Copying from INSIDE a code block yields plain text everywhere, never a re-created ``` fence. `SmartClipboard` handles the `copy`/`cut` DOM events directly (via `handleDOMEvents`, which ProseMirror runs BEFORE its built-in `serializeForClipboard`): when the selection lies entirely within one code block (`selectionInsideCodeBlock` -- `$from.parent.type.spec.code && $from.sameParent($to)`; a whole-block `NodeSelection` fails this because `$from.parent` is then the doc), it writes the raw `textBetween(from,to,'\n')` to BOTH `text/plain` AND a plain `text/html` (HTML-escaped lines joined by `<br>`, no block wrapper, so a paste merges inline into e.g. a prose paragraph), `preventDefault()`s, and (for cut) deletes the selection. Providing plain HTML -- not clearing it -- is required: with no HTML, ProseMirror's paste routes text through tiptap-markdown's markdown parser (so `- x` would become a list). Whole-block copies and the code-block copy button are untouched (they fall through to the default path / their own `writeText`).
- Backtick-wrap (`BacktickWrap` extension): a `handleTextInput` intercepts a lone `` ` `` typed over a NON-EMPTY, single-line selection and runs `toggleCode()` (wrap in inline `code`) instead of replacing the selection. Bails if inside a code block (`$from.parent.type.spec.code`), if the range contains a `\n` (`doc.textBetween(from,to,'\n')`), or if there's no selection -- so a collapsed cursor still types a literal backtick.
- Paste dedent (`transformPastedText` editorProp): before tiptap-markdown parses pasted plain text, `dedentPastedText()` strips the whitespace prefix common to every non-blank line. Markdown copied from a nested position (e.g. an indented Obsidian list sub-tree) arrives with a leading tab / 4 spaces on every line, which markdown-it reads as an indented code block instead of a list; removing the shared indent restores the list while keeping deeper relative nesting. Skipped when the second arg (`inCode || plainText`) is true, so pasting into a code block or a Shift+plain paste stays verbatim. NOTE: `transformPastedText` only runs on the TEXT clipboard path -- ProseMirror's rule is `asText = text && (plainText || inCode || !html)`, so when the clipboard also carries `text/html` (Obsidian and most editors always do) it takes the HTML path and this never fires. The `handlePaste` interceptor below is what actually fixes real-world list pastes; `dedentPastedText` remains the shared helper both call.
- List-paste interceptor (`handlePaste` editorProp): the robust fix for pasting bulleted/numbered lists (esp. from Obsidian, whose clipboard always includes `text/html`). When the clipboard's `text/plain`, after `dedentPastedText()`, has a first non-blank line matching a list marker (`[-*+]` or `\d+[.)]`), it bypasses the HTML path entirely and routes the plain text through MDE's own file-load pipeline (`escapeBulletNumbers` -> `splitLooseLists` -> `parser.parse` -> `cleanParsedListHtml` -> `PMDOMParser.parseSlice` with `context: $from` -> `replaceSelection`), so a pasted list is structurally identical to a loaded one (proper nesting, tight lists, task checkboxes). `escapeBulletNumbers` backslash-escapes an ordered marker that directly follows a bullet on the same line (`- 1. x` -> `- 1\. x`) so it stays a literal bullet (matching Obsidian) instead of collapsing into an empty parent bullet + ordered sub-list per CommonMark. The interceptor bails (returns false, default path runs) for non-list text, Shift+plain paste (`view.input.shiftKey`), pastes into a code block, and non-text (image) clipboards -- so prose, Word tables (`text/html`), and code paste unchanged. Reaches the parser via `editorRef` (set in the onReady effect) to avoid a use-before-define on the `editor` const. Merging a pasted list into an existing list item at a boundary keeps ProseMirror's native list-paste behavior (a leading empty item / last-item join can occur); the common case -- pasting onto an empty line or empty doc -- is clean.
- Leading-paragraph guard (`LeadingParagraph` extension): an `appendTransaction` prepends an empty paragraph (with `addToHistory: false`) whenever `doc.firstChild` is a `codeBlock`, so a document can never START with a code fence -- there's always a block above it to place the cursor. Self-healing (once a paragraph is first, it won't re-fire) and, on initial load, folds into the clean-doc snapshot so it doesn't mark the buffer dirty. Mirrors the existing trailing-block behavior at the end of the doc.
- Outline active heading: `DocumentOutline` highlights (blue, `.outline-item.active` -> `var(--accent)`) the last heading whose top has scrolled to/above the editor viewport's top reading line. A scroll listener on the scroll container (`editor.view.dom.parentElement`, i.e. `.editor-content`) recomputes on rAF; the reading line is `scrollerTop + paddingTop + 4` so the first heading counts as active at the top of the document. Headings are walked in document order with an early break (once one is below the fold, the rest are too).
- Tooltips: toolbar buttons and the fold caret use a shared CSS `[data-tooltip]::after` bubble (0.45s hover delay, themed via `--tooltip-bg`/`--tooltip-text`). Toolbar buttons set `data-tooltip` + `aria-label` (not `title`) with platform-aware shortcut hints (e.g. "Bold selection (Cmd + B)"); `MOD` is `Cmd` on darwin else `Ctrl`. The fold-caret tooltip is positioned to the right of the caret via a `.fold-caret[data-tooltip]::after` override.
- `open-file` with no window: a closed-but-not-quit app (macOS dock) opening a file creates a window via `createWindow(null, filePath)`, passing the path as `pendingFile` in `WindowState`. The renderer PULLS it on mount via the `get-pending-file` IPC (which clears it), rather than the main process PUSHING `open-file` on `did-finish-load` -- the push raced the renderer registering its listener, causing intermittent empty-screen loads.
- Fold state persistence: stored in `mde-state.json` as `foldState: { [filePath]: number[] }` -- arrays of 1-based markdown line numbers. On fold/unfold, `foldPosToLineNumbers()` serializes the markdown and matches folded items' text to line numbers. On file load, `lineNumbersToFoldPositions()` matches persisted line numbers back to doc positions by text content. Both functions use `stripInlineMarkdown()` to strip bold/italic/code/link/escape formatting before comparing. File rename (`rename-file` IPC) migrates fold state keys. External file reloads (silent and conflict-banner) save/restore fold state around `deserializeInto`. Currently line-number-only; if folds are frequently lost from external edits, a djb2 hash of each line's text prefix can be added as a secondary matching fallback.

## Testing

Playwright in Electron mode. Tests live in `tests/`. Run with `npm test`. The `pretest` script in package.json runs `electron-forge package` to build the `.webpack/` bundle before tests execute. To skip the rebuild when iterating on tests without source changes, run `npx playwright test` directly.

**Tests MUST be headless.** No windows should pop up when tests run. The main process checks for `--test-headless` in `process.argv` and sets `show: false` on the BrowserWindow. The test helper passes this flag automatically via `electron.launch({ args: [mainPath, '--test-headless'] })`.

**When troubleshooting test failures, run one test or one grep pattern first**, not the full suite. The full suite takes \~20s; a single test takes <1s. Use `--grep "test name fragment"` to isolate.

**All features need E2E test coverage.** Conversion features (PDF, DOCX import) are especially important to test since they depend on external libraries and webpack bundling behavior that can break silently.

All verification goes through E2E tests -- do not start the app interactively to check behavior.

**Sidebar tab selectors** use `[title="File Explorer"]` and `[title="Document Outline"]` (not text content) since tabs show icons.

**`tests/packaged.spec.ts` tests the PACKAGED artifact, not the dev tree.** The rest of the suite launches Electron against `.webpack/main` with the project's own `node_modules` present, so anything that only breaks inside `app.asar` (missing runtime deps -- see the `packageAfterCopy` note above) passes there and fails for the user. That spec extracts `out/**/app.asar` and `require()`s the externals out of it in a real Node process. It can't just launch the packaged binary: the Fuses config (`RunAsNode: false`, `EnableNodeCliInspectArguments: false`) prevents Playwright's Electron driver from attaching.

## CSS conventions

**Utility-first, with a Bootstrap-shaped vocabulary. GROW the utility layer -- don't route around it.** Compose from utilities before writing a component-specific class, and when you need a common semantic style that doesn't exist yet, ADD it to the `--- Utilities ---` block near the top of `src/index.css` rather than reaching for an inline style or a one-off class. That block is intentionally small today; it is meant to grow.

Naming and semantics follow **Bootstrap 5** so the vocabulary is guessable without reading the stylesheet. Use Bootstrap's actual class names -- `.small`, `.fw-bold` / `.fw-semibold` / `.fw-normal`, `.text-muted`, `.text-danger`, `.text-center`, `.d-flex`, `.gap-2`, `.mt-3`, `.align-items-center`, `.justify-content-between` -- and Bootstrap's spacing scale (`0`=0, `1`=.25rem, `2`=.5rem, `3`=1rem, `4`=1.5rem, `5`=3rem) and semantic color names (primary, secondary, success, danger, warning, info). Do NOT invent parallel names for things Bootstrap already names (`.text-gray` and `.fs-sm` were exactly that mistake, since removed). Semantic color utilities must resolve to the theme variables below, not literal hex -- e.g. `.text-danger { color: var(--danger-text); }`, `.text-primary { color: var(--accent); }` -- so they stay dark-mode correct.

Currently defined: `.small` (0.875em), `.fw-bold` (600), `.text-muted` (`var(--text-muted)`). Everything else is fair game to add on first real need -- add it because a component needs it now, not speculatively.

CSS variables for theming (defined in `:root`, `[data-theme="dark"]`, and `@media (prefers-color-scheme: dark)` blocks in `src/index.css`):

- Layout: `--bg`, `--bg-secondary`, `--bg-tertiary`, `--border`
- Text: `--text`, `--text-muted`
- Accent: `--accent`, `--accent-light`
- Danger: `--danger`, `--danger-bg`, `--danger-border`, `--danger-text`
- Info: `--info-text`
- Code: `--code-bg`, `--code-text`
- Highlight: `--highlight-bg`

When adding component styles:

- Use CSS variables for theme compatibility. Always set `color` and `background` on inputs and buttons so they work in dark mode.
- Component-specific classes are still right for a genuine multi-property component with hover/state (`.settings-row`, `.fold-caret`). Utilities are for the recurring single-purpose bits -- spacing, size, weight, color, flex.
- Keep ALL utility definitions in the one `--- Utilities ---` block in `src/index.css`, never scattered.
- A utility class with no definition is invisible -- it silently renders as body text. If styling looks unapplied, check the class actually exists before debugging anything else. (`.text-muted`, `.fs-sm` and `.fw-bold` were used 34 times across the components while defined nowhere.)
